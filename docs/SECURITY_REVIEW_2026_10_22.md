# Security review — 22 October 2026

This was a repository-wide security review, not a review limited to the working diff. Changes are limited to confirmed security defects, dependency remediation, regression tests, and this record. Existing project-management, preview, and setup changes were preserved.

## Scope and method

Reviewed the API and browser trust boundaries, authentication and onboarding, desktop enrollment/refresh, organization/team/project authorization, database roles and project RLS, provider credential handling, plugin OAuth/MCP transport, Cloud tool approvals and leases, file storage/previews, shared visual contracts, Rust worker and native sandbox, deployment configuration, and JavaScript/Rust/Python dependency locks. Used source tracing, repository-wide searches, targeted reproductions, current advisory databases, and regression/integration tests.

Threats considered include unauthenticated requests, malicious organization members and uploaded files, forged proxy headers, cross-project access, adversarial upstream responses, and untrusted sandbox commands. A clean dependency audit means no matching published advisories were returned; it does not establish absence of unknown vulnerabilities.

## Confirmed application findings and fixes

| Finding | Exposure | Remediation and evidence |
| --- | --- | --- |
| Uploaded SVG blob URLs inherit the application origin | High: SVG is inert as an image, but opening its blob URL as a document executes embedded script with application-origin access. A Chromium reproduction wrote an app-storage canary. | SVG previews now use opaque-origin data URLs. Raster previews retain revocable blob URLs. Chromium confirmed that the patched SVG still renders, has origin `null` when opened, and cannot write the app-storage canary. UI regression added. |
| Code provider gateway lacked Work's credential response protections | High: upstream errors, successful response headers, and stream chunks could expose the stored company key; automatic redirects could forward sensitive requests outside the configured endpoint. | Both gateway paths reject redirects, sanitize upstream errors/headers, redact literal and JSON-escaped key echoes across chunk boundaries, and sanitize stream exceptions. The same regression suite now exercises both products. |
| Authentication IP trust differed from Fastify's trust policy | Medium: Better Auth consumed client forwarding headers even when Fastify did not trust that peer, allowing authentication throttles and recorded IPs to be influenced independently. | The bridge overwrites a dedicated internal header with Fastify's resolved `request.ip`; Better Auth reads only that header. Tests cover untrusted peers, trusted proxies, and spoofed headers. |
| Sign-in callback normalization created external redirects | Medium: `/safe/..//evil.example` passes an initial same-origin parse but produces a network-path redirect when the normalized pathname is returned. | Validate the normalized pathname as well as its origin; reject control characters, backslashes, and non-string inputs. Tests preserve legitimate local paths and desktop-connect query strings. |
| Encoded static segments bypassed the web proxy's internal-route filter | Defense in depth: `/api/v1/%69nternal/...` bypassed the raw string check while Fastify decoded it to a worker route. Worker authentication remained required. | Apply the internal-path check after percent decoding. Proxy regressions cover encoded version and internal segments. The existing Caddy matcher was also exercised in a container and already blocks these forms. |
| CSV export formula guard missed control/whitespace prefixes | Low, user interaction required: an attacker-controlled actor name could place an active spreadsheet formula behind leading whitespace/control bytes in an administrator's export. | Prefix potentially active cells with an apostrophe, including control-prefixed values. CSV escaping and formula-prefix regressions pass. |
| Provider metadata and error bodies were bounded only after buffering | Medium availability risk: missing/false Content-Length or an endless error body could consume memory despite the apparent size checks. | Enforce the 8 MiB metadata limit while reading decoded bytes; reject oversized metadata and cancel rejected bodies. Provider refusals retain at most 4 KiB and cancel the stream immediately. Tests use endless streams, false lengths, split UTF-8, and failed streams. |

## Dependency remediation

- JavaScript: Vitest and its mocker are now 4.1.12; Vite resolves to 8.3.5. Mermaid is 12.2.0 with patched KaTeX. The repository's generated diagram flow was rendered and decoded in headless Chromium after the upgrade. `npm audit` returns zero vulnerabilities across production and development dependencies. See the [Vitest advisory](https://github.com/advisories/GHSA-qxg6-89mg-rqv8) and [KaTeX advisory](https://github.com/advisories/GHSA-238p-pmpm-9mq7).
- Rust: the worker lock now contains quinn-proto 0.11.19, rustls 0.23.46, rustls-webpki 0.103.16, and webpki-roots 1.0.10. An OSV batch check of all 206 registry packages returns no matches. The initial affected-package set was four packages; duplicate RustSec/GHSA aliases are not separate vulnerabilities. Relevant primary advisories include [TLS handshake validation](https://rustsec.org/advisories/RUSTSEC-2026-0285.html), [certificate validation](https://rustsec.org/advisories/RUSTSEC-2026-0382.html), and [root trust](https://rustsec.org/advisories/RUSTSEC-2026-0381.html).
- Python: the shared runtime's dependency update was imported through the existing vendor generator, after verifying that only `work-runtime/requirements.in` and `work-runtime/requirements.lock` differed. Pillow is now 13.0.0 and pypdf 6.21.2. The input constraints enforce `Pillow>=13.0.0` and `pypdf>=6.21.1` for future lock regeneration. The initial audit reported 29 advisories across those two libraries; the updated full lock returns no known vulnerabilities. See the [Pillow memory-corruption advisory](https://github.com/python-pillow/Pillow/security/advisories/GHSA-4rr5-89j8-mwwm) and [pypdf image-parser advisory](https://github.com/py-pdf/pypdf/security/advisories/GHSA-5hx5-vpf9-5wcv).

## Validation

- Final isolated PostgreSQL API suite: **731 passed, none skipped**. Both native and freshly built Linux workers were enabled. The Linux end-to-end cases exercised document creation, editing, PDF conversion, image rendering, manual/automatic approvals, and PDF/Word/Excel/PowerPoint previews through the API and durable database.
- Web suite: 854 passed.
- Rust worker: 25 passed, 1 Linux sandbox qualification test ignored on macOS.
- Cargo Audit 0.22.2 independently confirms zero vulnerabilities and zero warnings against RustSec commit `59ef7abf8ce56ea80fe7eba97ba3835449009fa4` (1,348 advisories). Run with `--no-fetch --no-yanked`; advisory checking was enabled, while yanked-version checks were excluded.
- Development/demo/vendor scripts: 11 passed.
- Typechecking, tracked-source ESLint, API compilation, and Webpack production web build passed. The default Turbopack build hit the environment's CSS-worker `Operation not permitted` failure; Webpack succeeded.
- Browser reproductions verified both the SVG-origin fix and actual Mermaid rendering. Caddy rejected all four ordinary/encoded internal-path variants and allowed an ordinary public path.
- The complete Python lock installed with hash verification in isolated host and Linux Python 3.13 environments. Document-kit self-tests passed. All **16 document-layout tests passed in the Linux build**, including the currency-font case that the bare macOS test environment could not supply.
- The fresh Linux production and sandbox-test images built successfully. The native sandbox denial suite passed under the production constraints: non-root user, read-only filesystem, all capabilities dropped, no-new-privileges, 64-process limit, 2 GiB memory limit, and a bounded temporary filesystem. It verified denial of secret/outside-file access, inherited descriptors, IP sockets, process-group escape, signals to other processes, shared IPC, and symlink creation while permitting required private Unix IPC.
- Initial builds encountered PyPI/CDN timeouts. The successful workaround used HTTPS requests through one DNS-advertised IPv4 endpoint with HTTP/1.1, then verified each of the **26 Linux wheels against the current vendored lockfile’s SHA-256 hashes**. A temporary copy of the Dockerfile changed only dependency retrieval to an offline wheel directory, retaining `pip --require-hashes`. The repository Dockerfile, TLS verification, and sandbox policy were unchanged. Rust and native-helper binaries were compiled from the current source. Qualified production image: `lori-enterprise-security-worker:20261022`, ID `sha256:f8c1f73157f078662f4797f1d993862b7f2eb5ad8891c533690ca1d1b824fa4b`.

## Qualification limits

This review does not claim a live-production penetration test, successful live provider/OAuth operations, deployed fixes, or exhaustive proof that every possible vulnerability has been eliminated. No production services, credentials, or user data were changed. Full-project lint also scanned existing ignored `.local` build/QA artifacts and failed there; tracked source passed without modifying those artifacts.

The shared runtime security update is now committed and published at `loridotsh/lori` commit `f1f24c868ecd63b56eb3b31463d3769f09489512`. Regenerating the vendor snapshot changed only its source commit and `sourceDirty: false` metadata; every vendored file hash remains identical to the tested snapshot. The `--release` integrity and source-parity checks pass. This closes the source-provenance gate without rebuilding or relabeling an old runtime package; deployment remains a separate action.
