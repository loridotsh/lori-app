# Product

## Users

Lori Enterprise serves two people in one company deployment. Administrators and
IT operators invite members, govern organization policy, review connected
devices, and keep access aligned with employment. Members authenticate once,
connect Lori desktop, and receive organization-managed configuration without
losing visibility into what is managed or personal.

## Product Purpose

Lori Enterprise is the self-hosted control plane for a company's Lori desktop
fleet. It establishes trusted organization identity, connects each desktop to a
specific member, distributes versioned policy and configuration, and lets
administrators revoke access immediately. Success means a member can move from
an invitation to a connected desktop without manually entering a server URL,
while the organization can explain and audit every resulting access decision.

The same deployment also provides Enterprise Cloud Work. Members switch between
**Manage** for enterprise controls and **Work** for a full cowork workspace in
the browser. Work includes private conversation history, attached files, approved
tools, document generation, assigned plugins and bundled skills, and private
memory managed in Settings. An enrolled Lori desktop accesses the same cloud
workspace. Local Work, Code, device folders, and local credentials stay separate;
transferring a file to Cloud is explicit.

The cowork interface follows Lori desktop's task hierarchy: a persistent history
sidebar, restrained conversation canvas, anchored composer, optional Files pane,
and dedicated Providers, Plugins, and Settings destinations. Success means a
member can complete and review a real task, recover an interrupted connection,
and understand approvals and file changes without losing their draft or place.
Browser Code execution is outside the Manage / Work scope.

## Brand Personality

Calm, authoritative, and precise. The interface should feel clean and premium
without becoming decorative. It should give administrators confidence that
security-sensitive actions are explicit, understandable, and reversible.

## Anti-references

Generic AI administration dashboards, decorative SaaS landing-page patterns,
glassmorphism, purple or multicolor gradients, novelty controls, excessive
rounding, and animation that does not communicate state. The product must never
hide policy consequences behind vague labels or silently alter personal state.

## Design Principles

1. Make authority visible: distinguish organization-managed configuration,
   member-owned configuration, and effective state everywhere.
2. Require deliberate security decisions: enrollment, revocation, and policy
   changes show their scope and consequence before they take effect.
3. Preserve a predictable control hierarchy: organization policy defines
   whether personal installations are allowed; managed assignments remain
   separately attributable.
4. Keep members oriented: invitation, authentication, desktop connection, and
   configuration sync form one continuous flow with recoverable states.
5. Earn trust through restraint: prioritize clear hierarchy, accurate status,
   accessible controls, and operational evidence over decoration.

## Accessibility & Inclusion

Target WCAG 2.2 AA. All workflows must support keyboard-only operation, visible
focus, semantic labels and errors, sufficient contrast, zoom and narrow
viewports, non-color state indicators, and reduced-motion preferences.
